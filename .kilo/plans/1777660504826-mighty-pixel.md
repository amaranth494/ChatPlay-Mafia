# Plan: Complete Core Gameplay Loop

## MVP Definition

ChatPlay Mafia MVP is a **fully playable single-player mafia family management game** where players run their crime empire entirely through message threads with AI-driven NPCs. No dashboards or direct actions—everything happens through conversation.

**Core MVP Experience:**
- Player starts as Boss with initial family (Consiglieri advisor + 3-4 NPCs)
- Player delegates missions via `/mission` commands to NPCs
- NPCs respond with AI-generated dialogue expressing mission outcomes
- Player can promote/demote NPCs, affecting relationships and capabilities
- Game state (money, territories, NPC states) persists across sessions
- Diegetic messaging interface—no HUD, all information through NPC conversations

**Success Criteria:**
- Players can start new game and receive initial Consiglieri greeting
- Players can delegate missions and receive character-appropriate NPC responses
- Players can manage family hierarchy and see relationship dynamics
- Full conversation loop works end-to-end without breaking immersion

## Current Project Status

The project has solid infrastructure foundations but is missing the core game simulation and AI integration that enables the MVP experience.

### What's Complete ✅
- **Infrastructure**: Railway deployment, Node.js/TypeScript backend, Next.js web client, environment setup
- **Database**: PostgreSQL schema defined, TypeScript interfaces created
- **WebSockets**: Server implemented with connection handling
- **UI**: Thread list, message display, composition interface, auth system (passkeys/OTP)
- **Advanced NPC Features**: Traits system, memories, emotional state, social simulation

### Major Gaps 🚧
The core gameplay loop is incomplete. Players can send messages and see threads, but there's no game logic processing their inputs or generating NPC responses.

## Critical Path Forward

### Phase 1: Core Simulation Engine (Week 1-2)
**Priority**: HIGH - This is the "source of truth" for game state

**Tasks**:
1. Implement Family entity (money, territories, hierarchy)

**Priority**: HIGH - Players need to be understood

**Tasks**:
1. Build command parser (`/mission`, `/promote`, etc.)
2. Implement natural language intent classification
3. Add validation layer for game actions
4. Integrate with Consiglieri for clarification

**Rationale**: The diegetic chat interface requires sophisticated intent parsing to translate player messages into game actions.

### Phase 3: AI Dialogue Generation (Week 4)
**Priority**: HIGH - NPCs need voices

**Tasks**:
1. Set up OpenAI Responses API client
2. Create NPC personality prompt templates
3. Implement context injection (state, events, relationships)
4. Add response rate limiting and memory systems

**Rationale**: The AI layer renders simulation results as character dialogue. This separation (simulation truth vs. AI expression) is core to the design.

### Phase 4: End-to-End Integration (Week 5)
**Priority**: HIGH - Wire everything together

**Tasks**:
1. Connect client to backend via WebSockets
2. Wire intent parser → simulation engine → AI dialogue → message delivery
3. Implement moderation layer (OpenAI moderation on input/output)
4. Test full loop: message → parse → simulate → respond → display

**Rationale**: Integration testing will reveal architectural issues and ensure the conversation flow works smoothly.

### Phase 5: Content & Polish (Week 6)
**Priority**: MEDIUM - Make it playable

**Tasks**:
1. Seed initial NPCs and family state
2. Create initial Consiglieri greeting and personality
3. Define mission types and tune difficulty
4. Add archive system for dead NPCs

**Rationale**: Need meaningful starting content to test gameplay before broader release.

## Technical Approach

### Architecture Principles
- **Separation of Concerns**: Simulation (truth) vs AI (expression) vs UI (presentation)
- **Server Authoritative**: All game logic runs on backend, client is thin messaging interface
- **Diegetic Design**: No HUD/stats - all information through NPC conversations

### Database Migration Strategy
Current code shows advanced NPC simulation but database schema may need expansion for full game state.

### Testing Strategy  
- Unit tests for simulation logic (deterministic outcomes)
- Integration tests for message flows
- Manual playtesting for conversation feel

## Risk Mitigation

**R1: AI Costs Scale Unpredictably**
- Implement prompt caching, shorter contexts, rate limiting
- Monitor usage and set budgets

**R2: NPC Consistency Across Sessions**
- Store conversation memory in database
- Inject structured context on each AI call

**R3: Intent Parsing Ambiguity**  
- Explicit `/command` system as primary interface
- Consiglieri handles clarification for natural language

**R4: Moderation False Positives**
- OpenAI moderation on both input and output
- Manual review queue for borderline cases

- **Moderation False Positives**: Layer approach (auto-block → review queue → manual)
